triggers - são automáticos diferente de procedure e fuctions

Eventos -> DML -> Insert, update e delete -> são os três eventos que o trigger vai manipular 

Ele tem um timing, ou "Before" ou "After"

E é feito em uma tabela.

Criar uma trigger para quando for adicionar uma pessoa, aumentar a quantidade de pessoas no bairro relecionado ao cliente inserido.

After insert on cliente

Delimiter $$

begin
	update bairro set baoqtdepessoa = baiqtdepessoa + 1 where baicodigo new.clibaicodigo
end$$

delimiter ;

delimiter $$

create trigger td_descrease_pessoas after delete on cliente
for each row
begin
	update bairro
	set baiqtdpessoas = baiqtdpessoas - 1
	where baicodigo = old.clibaicodigo
end$$

delimiter ;

Eu só posso ter um trigger para cada evento e timming, só um after update para clientes por exemplos, então tudo que quero fazer depois de atualizar o usuário tem que ser no bloco de after update

se no trigger eu atulizar uma tabela que possui um trigger tbm, ele aciona e faz juntando esses processos.

O trigger não é atômico, então se já aconteceu algumas operações e der erro em alguma operação na frente, ele não faz roolback.
